# 실제 HTTP 클라이언트 격리 비교


| 시나리오 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 첫 DNS 확인은 11.66.0.2, 실제 접속 시 127.0.0.1 | 내부 HTTPS 서버 도달, 200 | 주소 차단, 내부 서버 미도달 |
| 전역 기본값을 `follow_max: 5`로 변경한 상태에서 내부 주소로 302 | 리다이렉트 따라 내부 서버 도달 | 302 반환, 내부 서버 미도달 |
| HTTPS_PROXY가 로컬 프록시를 가리킴 | 프록시 도달, 프록시가 502 반환 | 프록시를 우회하고 허용 대상에 직접 연결, 200 |

DNS 사전 확인은 재바인딩 상황을 만들기 위한 별도의 합성 단계다. 원본 코드에는 사전 확인이 없다. 리다이렉트 전 결과는 명시된 전역 설정에서 관측한 값이며 Needle의 기본 `follow_max`는 0이다. `11.66.0.2`는 외부 공인 서버가 아닌 Docker 내부 네트워크의 테스트 주소다. 이 결과는 해당 고정 origin·IPv4·설정에서 관찰한 결과로, 모든 주소 표기나 클라이언트, 운영 환경에서 안전함을 보증하지 않는다.
