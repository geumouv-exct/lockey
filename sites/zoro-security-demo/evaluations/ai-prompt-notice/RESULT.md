# AI 수정 요청 실제 적용 평가

실행일: 2026-11-19. 대상은 저장소의 합성 예제 `examples/notice-preview`이며 실제 사용자 서비스가 아니다.

## 절차

1. 예제를 별도 작업 폴더로 복사하고, 잠금 파일의 `clsx`를 오프라인 캐시에서 설치했다.
2. Trace의 프로젝트 검사와 Zoro-1 Arena에 연결된 수정 요청 생성 API로 [요청문](prompt.txt)을 만들었다. 일반 텍스트 출력 의도와 방문자 입력 가능은 시나리오의 사용자 진술로 제공했다.
3. 요청문을 변경 없이 Codex CLI (`gpt-6.2-sol`, workspace-write 샌드박스)에 전달했다. 모델이 예제 작업 사본의 코드를 수정하고 테스트를 추가했다. [AI 응답](ai-response.txt)
4. AI가 수정한 코드와 원본에 같은 Trace 정적 규칙을 적용했다. 원본 테스트와 동일한 파일을 양쪽의 별도 작업 사본에 넣고 `npm test`를 실행했다. 원본 테스트 및 추가한 테스트를 포함한 AI 수정본 전체 테스트도 따로 실행했다.
5. 원본 및 수정본의 실제 `renderNotice` 함수를 로컬 브라우저에서 불러와 같은 무해한 HTML 입력 `<b>안녕</b>`을 출력했다.

## 결과

| 항목 | 수정 전 | 수정 후 |
| --- | --- | --- |
| Trace `dangerous-html` 정적 규칙 | `src/notice.mjs:5` 1건 | 미검출 |
| 동일한 기존 회귀 테스트 | 0개 통과, 1개 실패 | 1개 통과 |
| AI가 추가한 테스트 포함 전체 테스트 | 해당 없음 | 2개 통과 |
| 브라우저에 `<b>안녕</b>` 입력 | HTML 태그로 해석됨 | 입력 문자열 그대로 표시됨 |

AI는 `element.innerHTML = message`를 `element.textContent = message`로 바꾸고 일반 공지의 문구와 CSS 클래스를 확인하는 테스트를 추가했다. 긴급 공지 테스트는 기존 파일과 동일한 내용을 양쪽에서 실행했다. 테스트는 오프라인으로 설치한 같은 패키지 버전과 별도 작업 사본에서 수행했으며 컨테이너 격리 실행은 아니다.

## 한계

정적 규칙의 미검출은 모든 XSS가 제거되었다는 증명이 아니다. 예제에는 실제 방문자 입력이 이 함수로 전달되는 경로가 없어 도달성이나 실제 공격을 확인할 수 없다. 브라우저 검사는 지정한 함수와 무해한 한 가지 입력의 렌더링 차이만 확인한다. 하나의 예제와 한 번의 Codex 실행은 다른 AI 도구나 다른 프로젝트에서의 성공을 보장하지 않는다.
